# PIE/HWV × HW Leadership — Stakeholder Confluence Page (Proposed)

This document is a ready-to-publish Confluence page proposal for stakeholders (HW/EL leaders, PCE, PCT, UX, PIE). Copy the content below the line into Confluence as-is; Confluence macro suggestions are noted in *italics* where native widgets improve the experience.

**Design rationale (meets the three requirements):**
1. **Clear structure & logic** — top-down flow: health summary → decisions & guidelines → open topics by category → monthly check-in log → action tracker → references. Readers get status in 10 seconds, detail on demand.
2. **Clear main categories with extensible key topics** — five fixed categories (A–E); each is a table where new key topics are appended as rows. Concluded topics graduate into the **X-Team Guidelines** section, which becomes the reusable rulebook for future projects/programs.
3. **Monthly check-in tracking** — a dated check-in log with per-month snapshot rows, "changed since last month" markers on every category table, and an action tracker with status columns; page is updated at each monthly sync per the update protocol.

### Update protocol (how this page stays current)
1. **T-2 business days before sync:** project PIE leads update Category D/E registers; Eric refreshes section 1 summary and marks changed rows 🆕/🔼.
2. **During sync:** decisions recorded live; every escalation leaves with an owner + due date (per G-005).
3. **T+1 day after sync:** Eric promotes concluded topics to section 2 guidelines, updates the action tracker and check-in log, creates the `Check-in YYYY-MM` child page with minutes, and clears 🆕/🔼 markers.
4. **Anytime:** P0/P1 escalations do not wait for the monthly cycle — route to the next PD meeting and note in Category D.
